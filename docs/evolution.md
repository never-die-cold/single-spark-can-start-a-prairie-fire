# 方案演化与结论修正

本文件保存讨论中的技术脉络。它不是完整聊天记录，也不包含个人背景。

## V0：磁盘分块权重、共享种子、标量评分

各设备在本地磁盘保存相同权重；每轮选择一个参数块，以可复现随机方向进行正负两次前向计算，返回有限差分评分。所有节点从相同种子和评分重建参数更新。

优点：不存完整反向计算图；网络上不用同步整份梯度。代价：各节点仍需完整本地存储、更多前向计算、重复读取和方向估计噪声。

该核心机制有直接先例，包括 ES、MeZO、FedKSeed 和零阶卸载/并行工作。**不作为原创方向继续扩张。**

`prairie_fire/baselines.py` 保留了单进程模拟的 8 节点、33 参数 XOR 训练。权重位于临时磁盘映射文件，各副本从共同评分重建更新；运行后清理文件。它不测量真实网络、实际峰值内存或设备耗电。

## V1：精确局部响应、安全区域、并行局部上界

改为各设备保存不同子网络，融合网络在一个阶段内冻结。当融合 ReLU 开关不变时，其输出变化是特征变化的准确线性函数：

\[
\Delta\hat y=\sum_i A_i\delta z_i.
\]

对于平方损失，令 `v_i=A_i δz_i`，每个设备降低局部目标：

\[
\phi_i=e^\mathsf Tv_i+\frac N2\|v_i\|^2.
\]

由 `||Σv_i||²≤NΣ||v_i||²`，若全部 `φ_i≤0` 且没有越过安全区域，则同时提交不会增加该批数据的总损失。

缺点：完整响应矩阵大；安全半径会被一个接近零的无关 ReLU 卡住；`N` 因子可能很保守。`strict_parallel_checks` 保留该界的接口验证，不能当成完整网络训练的加速证据。

## V2：梯度锚定的压缩空间、切换误差预算、联合接受

当前实现见 [design.md](design.md)：

- 在输出空间选择包含当前残差的正交基，准确保留基准梯度。
- 把空间外线性响应写成显式尾部界，不能静默丢弃。
- 对 ReLU 切换影响建立余项界，允许小影响切换。
- 用所有设备摘要计算联合损失上界。
- 空间追加、模型/基准版本检查已实现；自动修复策略仍待实现。

一次新实现的固定种子完整运行记录在 [reference-2026-10-25.json](../results/reference-2026-10-25.json)。数值应以该文件和运行参数为准，不应手工调整代码以迎合聊天中先前的小数。

## 已修正的一个数值解释

讨论中的二维反例：遗漏空间外响应会把实际 `0.905` 的损失误报为 `0.405`。若使用实际尾部范数，能还原 `0.905`；当前代码使用更保守的 `τ||δ||`，得到上界 `0.910`。

测试明确区分实际误差与误差上界，不能将二者混用。

## 尚不能得到的结论

这些推导没有证明：任意模型可在任意弱设备集群上高效训练；设备数量能抵消任意通信损耗；更低硬件投入等于更低总成本；或当前方案具备学术首创性。
