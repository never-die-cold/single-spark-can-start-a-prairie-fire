# M1：从接口检查到真实子网络训练

记录日期：2026-10-25。实现见 `prairie_fire/training.py`；完整原始结果见 [m1-reference-2026-10-25.json](../results/m1-reference-2026-10-25.json)。这是单进程、可信节点、固定批次的 NumPy 小网络实验。

## 已构建的训练闭环

- 四个不同参数的 ReLU 分支，各为 `2 → 5 → 3`；融合网络为 `12 → 8 → 6`。
- 用独立教师网络产生 12 个固定样本的回归标签。每个节点只接收自己的两个输入维度；所有样本和标签在一个数据 epoch 中固定。
- 损失为每个样本的半平方输出误差范数，再对样本取平均；目标预设为 `0.01`，不是分类准确率。
- 每个候选最多执行 4 步真实本地参数 SGD，局部目标系数固定为节点数 `N=4`。节点在内部按代理目标缩步；共同提交仍由真实损失上界决定。
- 提案期间保留不可变的原参数快照，拒绝时不改动已提交状态。只有全部节点的同一候选通过联合判断后才同时替换参数。
- 每次成功提交上传实际特征并重新计算当前真实损失，后续候选与这个损失比较，不与旧上界比较。
- 每 8 轮单独训练一次融合网络，使用真实损失缩步；融合权重一旦改变立即废弃旧契约。
- 逐样本建立原有单样本证书，以整个批次的平均上界判断，不要求每个样本分别下降。

数据 epoch 包含输入、标签、样本 ID/顺序与预处理版本；契约代数和参数快照绑定提案，决定还绑定具体候选。刷新、扩基、已有参数改变或融合模型改变后，旧提案都不可提交。本实现使用确定性的 SGD，没有额外优化器状态或随机数据增强。

## 修复与对照

同一种子下六组运行共享完全相同的数据、网络结构和初始参数：

| 配置 | 反馈/接受方式 |
| --- | --- |
| 普通反向传播 | 每个本地步通过融合网络的真实链式梯度更新分支，最后以真实损失检查 |
| 不压缩响应 | 完整输出空间，保留非线性余项界和相同的共同提交机制 |
| 压缩、梯度锚定、按界刷新 | 初始秩 1，保留基准参数梯度，按失败预算修复 |
| 压缩、随机空间、按界刷新 | 不强制包含基准残差，额外计入被遗漏的残差范数 |
| 压缩、梯度锚定、周期刷新 | 每 4 轮重锚；拒绝只缩步，不自动扩基 |
| 压缩、随机空间、周期刷新 | 相同周期策略，使用随机空间的修正上界 |

普通反向传播也在分支阶段冻结融合模型，然后采用相同的融合训练周期，避免因训练日程不同而混淆对照。它更新分支的每一步都使用当前整个网络的真实梯度，不使用局部代理梯度。

按界刷新采用首个可测的启发式：比较尾部项与非线性项对损失上界的贡献；尾部项较大时从协调节点缓存的完整 Jacobian 查询遗漏响应的主方向并扩基。已经复用的契约仍失败时，在当前已提交参数重锚；否则缩步。每轮全局候选尝试最多 8 次。扩基保持原基准参数；同一融合阶段重锚保留已经增加的秩，融合模型变化后从初始秩重新构建。

随机空间取消梯度锚定以后，不能直接套用原公式。实现将遗漏的基准残差范数 `E` 加入空间外预算，即以 `E+D` 代替 `D`。对应反例与跨非线性候选的性质检查已经加入测试。

## 通信、计算与存储的记账边界

通信采用明确的逻辑单播模型：float64 载荷，每条消息额外加 128 字节元数据。该头部模型按三个 32 字节摘要和四个 int64 字段计数，不代表已实现序列化或真实网络协议。

账本包括初始输入分发、初始特征、每次构建/扩基/重锚后的整个批次响应矩阵及残差分发、尾部系数、每次成功或失败提案的摘要与决定、提交特征、融合模型 epoch 失效通知。基线复用协调节点已经拥有的首次特征，不重复计费。预安装代码、初始权重和中心端标签在所有配置中统一排除；这不是包含设备配置和数据采集的总成本。

所有响应 oracle、扩基方向 SVD、本地前向/反向、局部目标评估、全局缩步、拒绝重试和融合线搜索都有累计工作计数；VJP 计数包含其内部的前向重算。这些是工作类别计数，不是 FLOP 或电量测量。当前 oracle 查询完全在协调节点的密集模型和缓存上执行，没有远程查询流量；未来 JVP/VJP 分布后必须新增相应传输。

拒绝不查询候选真实损失、不上传完整候选特征，因此不会为了离线评估而隐去额外流量。拒绝可以是保守拒绝，不能解释成候选真实损失必然增加。接受后上传的特征用于真实当前损失核对；数值检查失败时不替换参数。

存储只报告观察点处保留的 NumPy 数组字节，计入节点原参数、候选参数、输入、特征、响应信息，以及协调节点的完整模型、证书、Jacobian、空间基和缓存。临时数组、BLAS 缓冲、解释器及真实设备分配峰值没有覆盖，不能作为实测峰值内存或显存节省。

## 本次结果

Python 3.12.14、NumPy 2.3.5；种子 `17, 31, 47`。每组最多 160 轮，分支学习率 `0.08`，融合学习率 `0.04`，其他参数完整写入 JSON。原始 `reference-2026-10-25.json` 未更改；M1 新结果独立保存，生成器标识为 `local-surrogate-backtracking-v1`。

| 种子 | 初始损失 | 反向传播最终损失 | 不压缩响应最终损失 | 压缩、锚定、按界刷新最终损失 |
| --- | ---: | ---: | ---: | ---: |
| 17 | 0.514218 | 0.041683 | 0.053373 | 0.056161 |
| 31 | 1.154778 | 0.094531 | 0.212941 | 0.213013 |
| 47 | 0.523972 | 0.065733 | 0.113921 | 0.115969 |

18 组运行的所有获准参数提交和融合更新均保持实际平均损失下降，没有观察到获准候选突破损失上界。**18 组都未在预算内达到 `0.01`**，包括普通反向传播。这个预算下还不能比较达到共同目标的时间、电量或流量，也不能把基线自身未达标归因于协议。

按界刷新的不压缩和压缩响应协议均重锚 160 次，每个契约最多成功提交一次。压缩、梯度锚定、按界刷新的成功/拒绝提案数分别为 `160/296`、`107/966`、`125/866`。候选内部有多步本地训练，但跨成功提交没有表现出稳定的契约复用。随机空间加按界刷新每个种子还发生 100 次扩基；随机空间加固定周期则没有一次分支候选获准，最终损失下降来自融合训练。这说明融合阶段和分支接受计数必须分别查看。

种子 17 的压缩协议记录 1,660,800 个逻辑字节，反向传播记录 2,214,784 个，但两者最终损失分别为 `0.056161` 与 `0.041683`；该固定轮数差异不能表述成同等效果下的通信节省。完整六组消融、每轮损失、契约事件、元数据和失败工作保留在 JSON 中。

本次达成了真实参数训练闭环和可审计的对照，**没有通过 M1 的共同目标效果与成本复用判据**。后续优先定位非线性预算和累计复用松弛造成的重建，见 [roadmap.md](roadmap.md) 的 M1.1；暂不扩张到真实设备或 Agent 管理层。

## 复现

~~~bash
python -m unittest discover -s tests -v
python -m prairie_fire.experiments --output results/latest.json
python -m prairie_fire.training --output results/m1-latest.json
~~~

CI 使用 `--seeds 17 31 --rounds 12` 做有界训练检查，覆盖六组配置。CLI 因安全检查失败而返回非零；没有达到目标会明确记录 `all_targets_reached=false`，不会将这个实验结果伪装成协议安全错误或性能成功。
