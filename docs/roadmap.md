# 下一阶段：先验证完整训练是否值得继续

## 已完成：M0 数学参考基线

- ReLU 融合网络及完整 Jacobian 参考 oracle。
- 基准梯度保持、尾部界、跨激活边界的余项界、联合接受。
- 新基/基准版本检查和单次空间追加。
- 可复现随机检查、关键反例、早期 XOR 基线和 JSON 记录。
- 当前结果不构成真实多机性能证据。

## M1：完整的小网络训练，当前唯一开发主线

目标：把接口变化替换成**真实子网络参数更新**，验证达到相同目标损失/精度的实际代价。

固定一个规模很小的回归或分类任务，采用 4 个局部分支和一个小型 ReLU 融合网络。先用 NumPy 或明确版本的自动微分后端完成单进程逻辑模拟，不立即加入网络和 Agent 管理层。

必须实现：

1. 子网络本地候选训练、参数快照、拒绝回滚和共同提交。
2. 融合模型冻结阶段与单独训练阶段；切换时使旧契约失效。
3. 固定批次/标签与样本版本规则，记录实际当前损失。
4. 尾部过大时扩基、余项过大时重锚的首个可测策略。
5. 所有查询、摘要、重试、提交特征和重建工作的完整逻辑账本。

同一网络、同一数据、同一初始参数的对照：

- 普通端到端反向传播。
- 不压缩的局部响应协议。
- 当前压缩协议。

消融至少覆盖：随机空间与梯度锚定空间、固定周期与按界刷新。省略尾部界的版本只能用来展示失败，不能作为有保证的正式方案。

继续判据：多种种子下达到预先固定的目标效果；接受/拒绝与真实损失一致；完整账本显示存在可以复用构建成本的区间。若长期只能做极小更新或每步都要重建，应先记录并分析失败，不扩张系统。

## M2：去掉完整 Jacobian 的 oracle 依赖

- 接口响应通过 JVP/VJP 和分页计算，不物化完整 Jacobian。
- 提供可验证且足够紧的尾部与非线性界。
- 测量真实峰值内存；协调节点空间和缓存不能漏计。
- 将证书计算时间与推导载荷节省放在同一张账本中。

## M3：真实通信与异构设备

- 先增加多进程/本地网络后端，再扩展到真实低性能设备。
- 处理版本、超时、缺失节点、重传和提交一致性。
- 记录实际传输字节、峰值内存、达到相同效果的墙钟时间。
- 基于实测功率或电表记录总电量，禁止用设备标称 TDP 代替能耗结论。

## 暂不开展

大模型预训练、任意 Transformer 保证、跨互联网志愿计算、复杂 Agent 调度、UI 和自动运维。它们都依赖 M1/M2 是否成立。
