# 下一阶段：先验证完整训练是否值得继续

## 已完成：M0 数学参考基线

- ReLU 融合网络及完整 Jacobian 参考 oracle。
- 基准梯度保持、尾部界、跨激活边界的余项界、联合接受。
- 新基/基准版本检查和单次空间追加。
- 可复现随机检查、关键反例、早期 XOR 基线和 JSON 记录。
- 当前结果不构成真实多机性能证据。

## M1：完整的小网络训练，初步实现，效果判据待满足

目标：把接口变化替换成**真实子网络参数更新**，验证达到相同目标损失/精度的实际代价。

固定一个规模很小的回归或分类任务，采用 4 个局部分支和一个小型 ReLU 融合网络。先用 NumPy 或明确版本的自动微分后端完成单进程逻辑模拟，不立即加入网络和 Agent 管理层。

已实现：

1. 子网络本地候选训练、参数快照、拒绝回滚和共同提交。
2. 融合模型冻结阶段与单独训练阶段；切换时使旧契约失效。
3. 固定批次/标签与样本版本规则，记录实际当前损失。
4. 按尾部/非线性预算扩基、复用后重锚和缩步的首个可测策略，以及固定周期对照。
5. 所有查询、摘要、重试、提交特征和重建工作的完整逻辑账本。

同一网络、同一数据、同一初始参数的对照：

- 普通端到端反向传播。
- 不压缩的局部响应协议。
- 当前压缩协议。

消融至少覆盖：随机空间与梯度锚定空间、固定周期与按界刷新。省略尾部界的版本只能用来展示失败，不能作为有保证的正式方案。

继续判据：多种种子下达到预先固定的目标效果；接受/拒绝与真实损失一致；完整账本显示存在可以复用构建成本的区间。若长期只能做极小更新或每步都要重建，应先记录并分析失败，不扩张系统。

实现与结果见 [m1-training.md](m1-training.md)、`results/m1-reference-2026-10-25.json`。安全检查通过不等于效果判据满足；保守拒绝也不表示候选的真实损失一定增加。

### 当前下一步：M1.1，定位重建瓶颈

在旧响应协议之外，按新的架构目标新增[精确边界重放与按需选步](replay-design.md)候选。它以小尾部副本、真实候选特征和参数重放替代 Jacobian 证书。须以同目标通信量、额外计算和节点存储共同评估；不能只报告省下的 Jacobian 或一次成功种子。原响应协议作为对照保留。

新路线当前出现了部分同目标通信收益，但没有一种已测公共设置让所有方案、所有种子同时达标；中间步菜单也未证明额外通信收益。冲突时按边际收益决定是否请求菜单的闸门已实现两轮迭代（见 [replay-design.md](replay-design.md) 的 M1.1 小节）。v2 在协调端已持有的 `{回滚, 终点}` 组合里零上传预搜索；v3 增加停滞跳过：种子 71 的 983 次冲突经诊断全部是停滞窗口（终点与全部中间步逐位等于已提交特征，菜单无新组合），跳过后五个发生冲突种子的菜单请求从 991 次降到 8 次，种子 71 的 gated 臂降至与只发终点同字节（−34.8%，诊断）。种子 47 保持达标并同目标省 5.8%；种子 31、5、93 以更高最终损失换字节。留出种子 `5, 71, 93` 均未达标，只作诊断。不把构造反例的改善当作实际成本优势。

- 温和调度族留出验证已完成（2026-10-30，见 [replay-design.md](replay-design.md)）：陷阱发生率 1/7 个种子、温和设置全部避开但平均略慢；种子 61/83 全设置同目标达标，gated 相对反向传播省 79.8–83.5%。没有一种设置全占优，参考设置保留为默认。下一步在更大任务（更多样本、更宽分支/融合）上复验闸门与中间前缀的相对价值，并检验温和调度的权衡是否随任务规模变化。
- 保持预设目标损失不变，先区分普通反向传播也未达标与协议额外保守性造成的差距。
- 对照冻结融合模型的更长阶段，记录同一契约实际成功提交次数，避免把多次失败重试当作复用收益。
- 分离输出空间遗漏和非线性余项造成的拒绝，检验更紧的分节点/分层变化界是否值得增加证书和摘要成本。
- 仍使用同起点、同目标、完整账本；未达标运行的固定轮数通信量只作为诊断。
- 在多种子目标效果与复用成本判据通过前，不推进真实设备、Agent 调度或大模型。

## M2：去掉完整 Jacobian 的 oracle 依赖

- 接口响应通过 JVP/VJP 和分页计算，不物化完整 Jacobian。
- 提供可验证且足够紧的尾部与非线性界。
- 测量真实峰值内存；协调节点空间和缓存不能漏计。
- 将证书计算时间与推导载荷节省放在同一张账本中。

## M3：真实通信与异构设备

- 先增加多进程/本地网络后端，再扩展到真实低性能设备。
- 处理版本、超时、缺失节点、重传和提交一致性。
- 记录实际传输字节、峰值内存、达到相同效果的墙钟时间。
- 基于实测功率或电表记录总电量，禁止用设备标称 TDP 代替能耗结论。

## 暂不开展

大模型预训练、任意 Transformer 保证、跨互联网志愿计算、复杂 Agent 调度、UI 和自动运维。它们都依赖 M1/M2 是否成立。
